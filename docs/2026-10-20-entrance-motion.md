# Появление элементов рабочего пространства

Основание: просьба добавить аккуратное, ненавязчивое появление элементов.
Референс: [Fluent 2 Motion](https://fluent2.microsoft.design/motion), разделы
Top level, Choreography, Accessible motion design. Перенесены короткое проявление
крупных областей, небольшое смещение локальных поверхностей и ограниченные задержки.

## Реализация

- Общий `useEntranceMotion`: 280 мс, задержка между группами 28 мс с пределом 84 мс.
- Небольшие блоки: прозрачность 0,35 → 1 и смещение 4 → 0 px. Крупные области
  и контейнеры с диалогами проявляются без смещения.
- Сетки дашборда, рабочего дня и аналитики раскрываются по смысловым группам.
  Строки таблиц, поля и отдельные отметки графиков не получают самостоятельных таймеров.
- Нижние группы появляются при первом попадании в видимую область.
  Исходный CSS не скрывает содержимое: при отсутствии API всё остаётся доступным.
- Переход запускается от идентификатора страницы/вкладки, не от изменения данных формы.
- Навигация остаётся стабильной; взаимодействие завершает активное появление.
  Клавиатурный фокус исключает повторное появление окружающей группы.
- При reduced-motion анимации отключены, включая изменение настройки во время работы.
  Наблюдатели и анимации освобождаются при смене страницы и размонтировании.
- Диалоги/шторки: 240 мс, меню: 140–180 мс. Все CSS-селекторы ограничены `.ep-root`.
  Лендинг и locked Hero не изменены; зависимостей не добавлено.

## Проверка

10 unit-проверок: ограничение времени, отсутствие вложенного каскада,
однократная прокрутка, очистка наблюдателей, взаимодействие, reduced-motion.
TypeScript и Vite build прошли; сборка сохраняет предупреждение о крупных chunks.

Браузер: дашборд → сегодня → дашборд, нижний график при прокрутке,
мобильный viewport 390 px, открытие формы, ввод и выход без сохранения.
Во время перехода наблюдались промежуточные opacity/translate; после завершения —
opacity 1 и translate none. При вводе форма и заголовок остаются непрозрачными.
