# Showcase Implementation Plan

**Goal:** Дать руководителю одну ссылку для показа всех восьми продуктовых экранов.
**Architecture:** DemoShell в product/main.tsx выбирается по demo=1, DemoFrame — по demoFrame. Обычный App сохраняет свой маршрут. Существующий стартовый экран выделяется в PracticeStart для повторного использования, ModuleSeedContext позволяет изолированно инициализировать демоданные без переадресации обычного аккаунта.
**Tech Stack:** React, TypeScript, iframe, scoped CSS, Vitest, Playwright. Без новых зависимостей.

## Ограничения

- Текущие незакоммиченные воронки сохраняются.
- Не менять Hero/лендинг, нормальную сессию, обычный экран авторизации и глобальные темы.
- Демо явно обозначено; код 123456 виден, никакой имитации подтверждённых платежей или отправок.

## Задачи

- [x] Чистая модель режима/URL/scope/reset и тесты: допустимые 8 экранов, mobile ->390px, некорректные значения, очистка только точного demo-prefix.
- [x] PracticeStart: выделить существующий DOM из App, сохранить действия первого шага. AuthPage: optional initialMode и audience, клиентский текст только для client; сохранение согласованной формы справа/фона.
- [x] DemoFrame: независимая практика и ModuleScopeContext/ModuleSeedContext, прямой рендер реальных Workspace/ClientPortal/Admin/PublicProfilePreview, переходы после регистрации и со страницы к заказу. Онбординг сохраняет свой путь, reset удаляет только его данные.
- [x] DemoShell: URL/history, нижняя панель, mobile iframe390px, footer вне iframe и вне перекрытия модалками. Reset/exit, корректный postMessage origin/source, состояния загрузки.
- [x] QA: тесты и build; browser все8 режимов, Back/reload, OTP дваварианта, начало и повтор онбординга, демодиалог и сменаэкранов, mobile настоящийviewport, page->booking, 320/390/1440, сохранность обычных session/practice/module keys. Независимый review. Синхронизировать только изменённые файлы в root и обновить локальный preview, без публикации.

## Результат проверки

- Production build и 478 тестов проходят.
- Chromium: все 8 экранов при 1440, 390 и 320 px; без горизонтального переполнения.
- Регистрация специалиста → онбординг; регистрация клиента → кабинет; страница → форма записи; повторный вход сохраняет данные.
- Reset, Back/reload, клавиатура и переключение из модалки проверены.
- Язык demo синхронизируется между оболочкой и экраном, обычные настройки языка и аккаунта не изменяются.
- Обычная регистрация и старт после выделения PracticeStart проверены.
- Независимое review: замечания по повторному входу и языку исправлены и проверены браузером.
- Локальная копия синхронизирована. Публикация и commit/push не выполнялись.
